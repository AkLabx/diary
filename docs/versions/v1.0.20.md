## 3. Engineering Decisions (Path A vs Path B)

### DEC-012 — Zero-Knowledge Metadata & Avatar Encryption
- **Chosen Path (Path A)**: Encrypt `mood`, `tags`, and `journal` inside AES-GCM entry ciphertext; encrypt profile avatars as `.bin` blobs via `encryptBinary`.
- **Rejected Path (Path B)**: Keeping plaintext `mood`/`tags`/`journal` SQL columns for server-side filtering and storing `.webp` avatars unencrypted.
- **Do-Not-Break Invariant**: Keep `mood`, `tags`, and `journal` columns null/static default; never upload unencrypted user avatars.

### DEC-014 — Non-Extractable CryptoKey & Biometry Invalidation
- **Chosen Path (Path A)**: Enforce `extractable: false` on Web Crypto keys, wipe keys on `SIGNED_OUT`, and configure `AccessControl.BIOMETRY_CURRENT_SET` on Android.
- **Rejected Path (Path B)**: Extractable keys cached across sessions and static biometric keys surviving OS enrollment changes.
- **Do-Not-Break Invariant**: Master `CryptoKey` remains non-extractable in memory and purges on sign-out or keystore invalidation.
