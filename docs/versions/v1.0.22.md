## 3. Engineering Decisions (Path A vs Path B)

### Decision ID: DEC-020 — CI Deploy Parity, Env-Only Test Auth & Live Edge Verification
- **Chosen Path (Path A)**: Enforce full PR-equivalent gates (`typecheck`, `lint`, `check:ci`) on `main.yml` with Node 22 and `fetch-depth: 0`; require strict `TEST_EMAIL`/`TEST_PASSWORD` env vars in `tests/e2e/auth-crypto-roundtrip.js` while scanning `tests/` in `verify-ritual.mjs`; keep `verify_jwt: false` on Edge Functions with in-function `auth.getUser()`.
- **Rejected Path (Path B)**: Relying solely on `pr-check.yml` and keeping `tests/` exempted or fallback-credentialed, or enabling gateway `verify_jwt: true` (which blocks browser `OPTIONS` CORS preflight).
- **Evidence & Trade-off**: Live tests confirmed `22/22` security checks passing (including `OPTIONS` allowlist/`Vary: Origin`, evil origin rejection, and `POST` HTTP `401`) and `100%` E2E crypto roundtrip fidelity with zero plaintext DB metadata.
- **Do-Not-Break Invariant**: Keep `main.yml` aligned with `pr-check.yml`, never exempt `tests/` from `verify-ritual.mjs`, and never reintroduce literal fallback credentials in test scripts.
